# Contributing to Aven

Bug reports, documentation fixes and code contributions are welcome.

## Before making a change

- Search existing issues and discussions for related work.
- For a substantial change, open an issue first to agree on its scope.
- Keep pull requests focused and describe the user-visible behavior, implementation and any migration or security impact.

## Development

The project uses Go for the server, agents and CLI, and Next.js with TypeScript for the web UI. See the root README for build requirements.

Useful checks before opening a pull request:

```sh
gofmt -w path/to/changed-file.go
go test ./...
cd web && npm run typecheck && npm run i18n:check
```

The project website (aven.turin.my) is a separate Laravel app in `website/`; run its tests with `cd website && composer install && php artisan test`.

Build all distributable binaries and the web UI with `make all`. Edit web sources under `web/`; the embedded UI assets are generated by the build and are not checked in.

## Translations

The web UI is available in Korean and English. Korean is the source language: wrap user-visible text in `t()` from `web/lib/i18n.tsx` and add the English translation to a dictionary in `web/lib/i18n/en/`.

```tsx
t("저장")                                   // "Save"
t("서비스 {count}개", { count })              // placeholders: "{count} services"
tr("{env}에 넣으세요", { env: <code>X</code> }) // sentences that contain elements
t("다음|shortcut")                          // same Korean, different English in this context
```

Keep the Korean key exactly as it appears in the UI, translate whole sentences rather than fragments, and keep the same `{placeholders}` in both languages. `npm run i18n:check` reports keys missing from the dictionaries, placeholder mismatches, conflicting translations, and Korean text that is not wrapped yet.

## Pull requests

- Explain the problem and the change in the pull request description.
- Include tests for behavior changes and update the relevant documentation.
- Call out breaking API, database migration, deployment or configuration changes.
- Do not include real credentials, customer data, private hostnames or generated build artifacts.
